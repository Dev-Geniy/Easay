# Cloudflare Worker: эксплуатация Easay 6.2

Сервис Easay развёртывается как **Cloudflare Worker**, без дополнительного Pages-проекта. Исходники: `worker/index.js`, `wrangler.toml`; статика в `public/`, сборка в `dist/`.

**Текущая конфигурация в репозитории:** `wrangler.toml` уже указывает на базу D1 `easay-certificates` с привязкой `EASAY_DB`. Переустанавливать биндинг или вручную создавать таблицы ради версии 6.2 не нужно, если существующее облачное окружение уже настроено.

Команды локального контроля:
```bash
npm test
npm run build
```

Публикация на Cloudflare: Workers Builds из main с командами сборки `npm run build` и деплоя `npx wrangler deploy`, при уже настроенном CI/CD.

Секреты Cloudflare (никогда не помещать в GitHub): `GROQ_API_KEY` — для ИИ; `CERT_HASH_SECRET` (не менее 24 символов) — для хеша идентификатора экзамена. `keep_vars=true` позволяет сохранить ранее настроенные секреты при деплое. Если этих секретов в облаке нет, серверные функции без настройки заработать не смогут — не утверждать обратное.

API: `/api/ai` работает через Worker, использующий `netlify/functions/ai.mjs` как модуль; `/api/exam` начинает/восстанавливает экзамен и принимает ответы; `/api/certificate` проверяет сертификат. Прямой GET `/api/ai` возвращает 405, а экзаменационный API без заголовка `x-easay-learner-id` не создаёт попытку.

Ограничения: одна новая попытка на браузер за 24 часа; восстановление активной до 45 минут; без D1 — только тренировочный экзамен. Сертификат — исключительно внутренний экзамен Easay, без проверки личности и завершения уроков по серверной базе. Наличие зелёного CI не доказывает успешное развёртывание.
